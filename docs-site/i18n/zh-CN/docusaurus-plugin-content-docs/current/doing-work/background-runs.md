# 后台运行

被发出去自己跑的活儿。**每一次运行都是一个独立的 agent,在自己的目录里工作**,所以你
关掉发起它的那个对话之后,它还在跑。

## 四种来源

| 来源 | 由谁发起 |
| --- | --- |
| **派发** | 你,在派发面板里手动发 |
| **定时** | 一个重复任务到点了 |
| **值守** | 一个 Bot 的值守到点了 |
| **协作** | 在协作模式下发一条消息 |

**四种最后都进同一个列表** —— 这也是为什么即使你从不手动派发,这个面板也值得看。

## 只在 OpenCLI 开着的时候运行

**这是本地 agent,不是服务器。** 必须在机器睡着时触发的东西,属于操作系统自己的调度器
—— `cron`、`launchd`、任务计划程序。

说得这么直白,是因为另一种情况是**一个任务悄悄地从来没跑过**。

## 同时跑几个

默认三个。每一个都是完整的 agent、有自己的模型调用,所以**超出机器喂得动的数量,只会
让它们全都变慢,而不是更快完成**。这个数字在面板里是个控件,改完不用重启。

上限是十六,**这不是口味问题**:再往上,运行就不再是各自推进,而是在抢同一份权重。

## 目录,以及为什么运行会被扣住

一次运行的沙箱可以写**它工作目录里的任何地方**。所以那个目录不是个「方便设置」——
**它就是这次运行能改动的全部范围**。

因此,一次运行只有在目录是产品已知的那几种时才允许开始:

- 在工作区里
- 在某个部门自己的目录里
- 在你按名字授权过的地方

**其他一律扣住**,出现在派发面板的**等你授权**下面,带一个「允许这个目录」按钮。
授权一个地方,会**放行所有在等它的运行**。

如果你的审批设置是**从不问**,那什么都不会被扣住 —— 把审批关掉的人已经把话说清楚了,
产品不会去推翻自己提供的设置。

## 看一次运行

**输出是 agent 产出多少显示多少**,不是跑完才有。一个十分钟的运行,这十分钟都是可读的。

## 把一次运行接过来

一次跑完的运行可以**接管成普通对话**:「在对话中继续」会在同一个目录开一个新线程,
**并且把这次运行被要求做什么、报告了什么,都已经放进上下文**。

运行本身是没法对话的。**这是回到里面去的方式。**
