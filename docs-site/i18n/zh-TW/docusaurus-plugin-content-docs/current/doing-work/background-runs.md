# 後臺執行

被發出去自己跑的活兒。**每一次執行都是一個獨立的 agent,在自己的目錄裡工作**,所以你
關掉發起它的那個對話之後,它還在跑。

## 四種來源

| 來源 | 由誰發起 |
| --- | --- |
| **派發** | 你,在派發面板裡手動發 |
| **定時** | 一個重複任務到點了 |
| **值守** | 一個 Bot 的值守到點了 |
| **協作** | 在協作模式下發一條消息 |

**四種最後都進同一個清單** —— 這也是為什麼即使你從不手動派發,這個面板也值得看。

## 只在 OpenCLI 開著的時候執行

**這是本地 agent,不是伺服器。** 必須在機器睡著時觸發的東西,屬於操作系統自己的調度器
—— `cron`、`launchd`、任務計划程式。

說得這麼直白,是因為另一種情況是**一個任務悄悄地從來沒跑過**。

## 同時跑幾個

預設三個。每一個都是完整的 agent、有自己的模型調用,所以**超出機器餵得動的數量,只會
讓它們全都變慢,而不是更快完成**。這個數字在面板裡是個控制項,改完不用重啟。

上限是十六,**這不是口味問題**:再往上,執行就不再是各自推進,而是在搶同一份權重。

## 目錄,以及為什麼執行會被扣住

一次執行的沙箱可以寫**它工作目錄裡的任何地方**。所以那個目錄不是個「方便設定」——
**它就是這次執行能改動的全部範圍**。

因此,一次執行只有在目錄是產品已知的那幾種時才允許開始:

- 在工作區裡
- 在某個部門自己的目錄裡
- 在你按名字授權過的地方

**其他一律扣住**,出現在派發面板的**等你授權**下面,帶一個「允許這個目錄」按鈕。
授權一個地方,會**放行所有在等它的執行**。

如果你的審批設定是**從不問**,那什麼都不會被扣住 —— 把審批關掉的人已經把話說清楚了,
產品不會去推翻自己提供的設定。

## 看一次執行

**輸出是 agent 產出多少顯示多少**,不是跑完才有。一個十分鐘的執行,這十分鐘都是可讀的。

## 把一次執行接過來

一次跑完的執行可以**接管成普通對話**:「在對話中繼續」會在同一個目錄開一個新執行緒,
**並且把這次執行被要求做什麼、報告了什麼,都已經放進上下文**。

執行本身是沒法對話的。**這是回到裡面去的方式。**
