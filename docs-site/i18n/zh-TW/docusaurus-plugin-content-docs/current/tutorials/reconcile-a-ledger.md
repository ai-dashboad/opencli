# 對一次賬,從頭到尾

**二十分鐘,用一個本地模型。** 做完之後你會有一個部門,它每天早上拿兩個文件互相核對,
並且在發現超過你設定的門檻的東西時停下來問你。

這裡用的全是隨產品一起裝好的樣例資料,**什麼都不用准備**。

## 1. 建部門

**專案 → 或從一個現成的開始 → 財務。**

它會建好 `~/.opencli/workspace/finance`,往裡寫三個文件,並招兩個 Bot。

**那些文件裡的問題是特意埋的:**

| 文件 | 裡面是什麼 |
| --- | --- |
| `ledger.csv` | 你的賬上怎麼記的 |
| `statement.csv` | 銀行怎麼說的 |
| `overdue.csv` | 過了日期的發票 |

## 2. 先手動問一次

打開這個部門,輸入:

```
拿 ledger.csv 和 statement.csv 對賬。列出所有對不上的行，
帶憑證號和金額，並說說你認為發生了什麼。
```

**看它怎麼做。** 一個適合幹這個的模型會用工具讀兩個文件,並用行和憑證號回答。
不適合的那個要麼讓你把內容黏過去、要麼泛泛而談 —— **如果是那樣,問題在模型,不在設定。**
[測一下它](/reference/checking-a-model)。

## 3. 變成一個值守

Bot 做了一次。**值守讓它自己到點。**

打開 **對賬 Bot**,設它的值守:

| 字段 | 填什麼 |
| --- | --- |
| **做什麼** | 逐行比對 `ledger.csv` 和 `statement.csv`。列出對不上的,帶憑證號和金額。 |
| **規則** | 金額差小於 1.00 算捨入,忽略。 |
| **什麼時候問你** | 任何單筆超過 10000。 |
| **多久一次** | 24 小時 |

**「規則」和「做什麼」分開是有原因的**:活兒每天都一樣,而那個門檻是某個人會回頭修訂的
政策。合成一段之後,改那個數字就得重讀整段指令才能找到它。

## 4. 看它停下來

**立即執行。** 樣例資料裡有一條超過門檻的差異,所以**這個值守不會跑完** —— 它會帶著那個
答不了的問題出現在**員工 → 等你答覆**裡。

**那就是這個功能的全部意義。** 它幹了活、走到你划的那條線、然後停住,而不是自己拍板。

回答它。**你的回答會帶進下一次執行**,所以它不會為同一件事問第二遍。

## 5. 把結果傳下去

財務部還帶了第二個 Bot,**催收**。在對賬 Bot 的**可以交給**清單裡勾上它。

現在一次找到未符合行的執行可以把它們傳下去 —— **連同它做了什麼、產出了哪些文件** ——
催收 Bot 就能起草催款郵件,不用別人再告訴它背景。

**員工 → Bot 之間傳遞的工作**裡能看到這條鏈,並且會**標出那些因為跳數用完而停、
不是因為幹完了的**。

## 你現在有了什麼

- 一個 agent 可以寫、且只能寫的目錄
- 不用你發起就會發生的活兒
- **一條寫下來的、它會停下來問你的線**
- 一個接著第一個往下幹的 Bot

## 首先該改什麼

**那個門檻。** 10000 是例子裡的數字。**你的不是。**

**那些規則。** 「差額小於 1.00 算捨入」對某些賬本成立,對另一些不成立。

**那個周期。** 24 小時是個習慣,不是法律。**一個在銀行入賬之後跑的值守,比一個在午夜跑
的有用。**
