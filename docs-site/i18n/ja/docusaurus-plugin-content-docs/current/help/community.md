# 助けを得る、そしてどこで言うか

## 訊く前に

**最初の一週間に起きることの大半は**[故障対応](/help/troubleshooting)にあり、
*自分の供給元は対応しているか* の答えは[供給元](/getting-started/providers)にあります。

**エージェントが話すのにファイルには一切触れないなら、それはほぼ必ず設定ではなくモデルです** ——
設定に一晩を費やす前に[試してください](/reference/checking-a-model)。

## どこで訊くか

**[GitHub Issues](https://github.com/ai-dashboad/opencli/issues)** —— バグ、および
**文書に書いてあることと違う振る舞いをしたもの**すべて。

**[GitHub Discussions](https://github.com/ai-dashboad/opencli/discussions)** ——
質問、思いつき、そして「これはこういうものなのか」。

**チャットサーバーはまだありません。** **座る値打ちがあるだけの人数になったら**できます。
**空の部屋は誰の助けにもなりません。**

## どんな報告が動かしやすいか

**四行**。そして**たいていの報告にはそれがありません**:

1. **モデルと供給元を、名前のまま** —— Ollama の `qwen3-coder:30b`、
   「ローカルのモデル」ではなく。
2. **何をさせようとしたか**、そのままの言葉で。
3. **何が起きたか**、そして**何を期待していたか**。
4. **`~/.opencli/log` の、失敗の前後五十行。**

**貼る前に、そのログ行に鍵が入っていないか見てください。**

## 何が一番助かるか

**モデル表の一行。** [モデルを試す](/reference/checking-a-model)は固定の課題一つ、
およそ五分です。**表が短いのは走らせたものしか載せていないから**であり、
**負の結果は正の結果と同じだけの値打ちがあります** ——
**動かなかったモデルのことは誰も投稿しないので、全員が発見し直します。**

**翻訳、あるいはその一箇所の修正。** 十が同梱されています。
そのどれも**残りに触らずに一行ずつ直せます** ——
[多言語](/configuration/languages)を見てください。

**あなたが実際にやろうとしたことを教えてください。** 同梱の部門と流れは
**人が何を必要とするかの推測から書かれています**。
**あなたが手を伸ばして見つからなかったものこそ、言える中で一番役に立つこと**です。
