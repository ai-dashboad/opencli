# バックグラウンド実行

**単独で走らせるために送り出した仕事**です。**それぞれの実行は独立したエージェント**で、
自分のディレクトリを持つので、**始めた対話を閉じても続きます**。

## 始まり方は四つ

| 出どころ | 誰が始めるか |
| --- | --- |
| **Dispatch** | あなたが Dispatch パネルで手動で |
| **定時タスク** | 繰り返しタスクの時刻が来て |
| **当番** | ボットの当番の時刻が来て |
| **Cowork** | Cowork モードでメッセージを送って |

**四つとも同じ一覧に行き着きます。** 手動で何も派遣しない人でもこのパネルを読む価値が
あるのは、そのためです。

## OpenCLI が開いている間だけ走ります

**これはローカルのエージェントであってサーバーではありません。** マシンが眠っている間に
発火しなければならないものは、**OS のスケジューラー** —— `cron`、`launchd`、
タスク スケジューラ —— に置いてください。

はっきり書いてあるのは、そうでない場合の結末が**黙って一度も走らなかったタスク**だからです。

## 同時に何本

**既定で三本。** 一本ずつが自分のモデル呼び出しを持つ丸ごとのエージェントなので、
**マシンが養える以上に増やすと、早く終わるどころか全部が遅くなります**。この数はパネルの
コントロールで、**再起動なしで効きます**。

**上限は十六**で、これは趣味の問題ではありません:それを超えると、
**実行は前に進まなくなり、同じ重みを取り合い始めます**。

## ディレクトリと、実行が保留される理由

実行のサンドボックスは**作業ディレクトリの中ならどこにでも書けます**。
つまりそのディレクトリは便宜ではなく、**その実行が変更しうる範囲のすべて**です。

ですから実行が始められるのは、そのディレクトリが**この製品がすでに知っている場所**のときです:

- ワークスペースの中
- ある部門自身のディレクトリの中
- **あなたが名指しで許可した場所**

それ以外は**保留**され、**あなた待ち**の下に *このディレクトリを許可* ボタンつきで現れます。
**ある場所を許可すると、それを待っていた実行がすべて解放されます。**

承認の設定が **一切訊かない** なら、**何も保留されません**。承認を切った人は
そう言ったのであり、**製品は自分が用意した設定を上書きしません**。

## 様子を見る

**出力はエージェントが出すそばから現れます**。実行が終わったときではありません。
十分かかる実行は、**その十分のあいだずっと読めます**。

## 引き取る

**終わった実行は普通の対話として続けられます**:**Continue in a chat** が同じディレクトリで
新しいスレッドを開き、**その実行が何を頼まれ、何を報告したかがすでに文脈に入っています**。

**実行そのものには話しかけられません。** これがその中に戻る道です。
