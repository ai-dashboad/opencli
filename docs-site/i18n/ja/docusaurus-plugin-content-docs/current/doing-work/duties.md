# 当番

**当番とは、ボットが一定間隔で行う仕事**で、**独断で決めるべきでないところに来ると止まって
あなたに訊きます**。

**最後の部分が要点です。** プロンプトをタイマーで回すだけなら何にでもできます。
これが実務で役に立つのは、**何を自分で片づけてはいけないかが前もって伝えてある**からです。

## 四つの欄

```
何を          ledger.csv と statement.csv を一行ずつ突き合わせ、
              合わないものを参照番号と金額つきで挙げる。

規則          1.00 未満の差は端数。無視する。

上げる条件    どれか一行でも 10,000 を超えたら。

間隔          24 時間
```

**「何を」と「規則」はわざと分けてあります。** 仕事は毎朝同じですが、
**返金の上限は誰かが見直す方針**です。一つのプロンプトに混ぜてしまうと、
**その数字を変えるのに指示全体を読み直す**ことになります。

**「上げる条件」は条件式ではなく言葉で書きます。** これは**製品が評価するのではなく、
モデルに義務として渡されます** —— つまり**読むモデルと同じだけしか当てになりません**。
**確かめられる形で書いてください**:*どれか一行でも 10,000 を超えたら*、
*何かおかしければ* ではなく。

## 上がったときに何が起きるか

**当番は止まります。** 答えられなかった問いとともに **Bots → あなた待ち** に現れ、
**あなたが返事をするまで二度と走りません**。

**あなたの答えは次の実行に持ち越されます**ので、ボットが同じことを二度訊くことはありません。

**すでに訊いた当番は、二つ目の問いを立てません** —— 開いている方を繰り返します。

## 何を覚えているか

**当番は実行の間にメモを保ちます。** 一つ学んだ実行は**その一つを書き留めるだけ**で、
すでに知っていたことを言い直す必要はなく、**途中で失敗した実行が残りのメモを道連れにすることもありません**。

**空の値を書くのが、意図して忘れさせるやり方**です。

## どこで走るか

**ボットの部門ディレクトリの中**で、そこが**その実行が書き込める範囲のすべて**です。
別の場所を指した当番は、**あなたがその場所を名指しで許可するまで保留されます** ——
[サンドボックスと承認](/configuration/sandbox-and-approvals)を見てください。

## 当番と、定時タスク

**どちらもプロンプトをタイマーで回します。** 違いは**何に属しているか**です。

| | 属している先 | 上げる | 覚える |
| --- | --- | --- | --- |
| **当番** | 部門の中のボット | する | する |
| **定時タスク** | 何にも属さない | しない | しない |

*毎朝九時に、変わったことを教えて* には**定時タスク**を。
**方針がくっついた仕事**には**当番**を使ってください。
