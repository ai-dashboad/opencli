# スキル

**スキルとは、必要になったときエージェントが参照する手順書**です ——
**毎回プロンプトに貼り付ける代わりに、一度書き留めた手順**。

## 同梱されているもの

**六つの流れが製品についてきて、どのディレクトリでも動きます**:

| スキル | 何をするか |
| --- | --- |
| `spreadsheet-review` | 行の並んだファイルを、そこに書かれた規則に照らし、破っている行を**行番号つき**で報告する |
| `weekly-report` | ある期間にここで**実際に変わったこと** —— 済んだもの、進行中、そして判断が要るもの |
| `inbox-triage` | メッセージを「何を求めているか」で仕分け、**人が答えねばならないもの**に印をつける |
| `document-compare` | 二つの草案のあいだで**中身が変わったところ**を、**言い回しだけが変わったところ**と分けて示す |
| `meeting-notes` | 書き起こしを、決定事項・担当者つきのアクション・未解決の問いに |
| `records-review` | 記録の束から**確かめる価値のあるもの**を挙げ、**出どころのメモを引用する** |

もう二つ、継承したものは**スキルを書くこと・入れることそのもの**についてです:
`skill-creator` と `skill-installer`。

## どこから来るか

| 範囲 | ディレクトリ |
| --- | --- |
| 同梱 | `~/.opencli/skills/.system` —— アプリ更新時に書き直されます |
| あなたのもの | `~/.opencli/skills` |
| このプロジェクトのもの | 作業ディレクトリの `.opencli/skills` |

## 書く

`SKILL.md` を持つディレクトリ。その front matter が、それが何であり、
**いつ使うか**を述べます:

```markdown
---
name: invoice-check
description: Check invoices against our payment rules and report what breaks
  them. Use when asked to review, check or audit a file of invoices.
metadata:
  short-description: Find invoices that break the rules
---

# Invoice check

## Find the rules before reading the rows
...
```

**`description` こそ、エージェントが依頼を突き合わせる相手**です。
そのスキルが***何であるか***しか書いていない説明は、**いつ当てはまるかをモデルの推測に任せます** ——
**同梱のスキルはどれも「どんなときか」を名指しします**し、あなたのものもそうすべきです。

## 何が効くスキルにするか

**同梱の六つを読むのが形を掴む一番早い道**ですが、三つのことが繰り返し出てきます:

- **何を、どの順で読むかを言う。** 「古いものから」は本物の指示です。
  「記録を確認する」は違います。
- **何を作るかを言う。** 名前のついたファイル、あるいは明示された構造。「要約」ではなく。
- **絶対にしてはいけないことを言う。** 同梱の診療記録スキルは**全体の三分の一をこれに費やしており**、
  だからこそ存在できます。

**痛い目で分かったことが一つ**:数字が重要なら、**その数字がどこから来なければならないかを言うこと**。
表計算スキルは行数を求めますが、**最初の実行はそれを記憶から述べて一つ間違えました**。
今は、**確認を行ったスクリプトから数が来ることを要求します**。

## 切る

各スキルには **Abilities → Skills** にスイッチがあります。
変更は**すでに走っている対話ではなく、次に開く対話**に効きます。
