# フォルダーを見張って、変わったことを報告させる

**十分。** 終わったときには、**あなたが選んだ周期で、あるディレクトリで動いたものを
短くまとめて書いてくれるもの**が手に入ります —— プロジェクト、共有ドライブ、
**誰かが物を置き続けるフォルダー**。

## 1. 対話をそのフォルダーに向ける

新しい対話を開き、入力欄の上のフォルダーボタンでディレクトリを選びます。

**これは見た目より重要です**:**エージェントは、対話が開いているディレクトリの中なら
どこにでも書けます**。そしてその外には書けません。
**フォルダーを選ぶことは、爆発半径を選ぶことです。**

## 2. まず一度、報告を頼む

```
このフォルダーに weekly-report スキルを使って。
```

`weekly-report` スキルは製品に同梱されています。**何が変わったかを割り出し** ——
フォルダーがリポジトリなら git から、そうでなければ更新時刻から —— 三つの節を書きます:
**終わったもの、進行中のもの、そして判断が要るもの。**

**最後の節こそ、これを読む理由です。**

## 3. 周期に載せる

**バックグラウンド実行 → 繰り返しを一つ組む:**

| 欄 | |
| --- | --- |
| **何をさせるか** | このフォルダーに weekly-report スキルを使う。`report-<date>.md` として保存する。 |
| **名前** | 週次レポート |
| **どのくらいの頻度で** | 7 日 |
| **どこで走らせるか** | 選んだフォルダー |

## 4. どこで走るのかを確かめる

**フォルダーがワークスペースの中でもなく部門でもない場合、最初の実行は始まらず保留され**、
*あなた待ち* の下に現れます。

**これは意図的です。** ディレクトリを許可するか、タスクを部門の中に移してください。

## 5. 最初の一本を読む

**Run now**、そして実行を開いて**出てくるそばから出力を読みます**。

**レポートが薄ければ、そのフォルダーの一週間が薄かった**のです ——
このスキルは**水増しする代わりに一行でそう言う**よう指示されています。
**空の一週間から水増しされたレポートは、人にレポートを飛ばすことを教えるからです。**

## 他人のフォルダーにこれをやる場合

**気をつける値打ちのあることが二つ。**

**エージェントは向けられたものを全部読みます。** そして**読み取りはどのモードでも
サンドボックスに制限されません**。**モデルの供給元に送りたくないものが入ったフォルダーを、
向ける先にすべきではありません** —— **モデルが自分のマシンにある場合を除いて**。
そのときは何も外に出ません。

**周期はあなたの注意より長生きします。** 一年間、週一で走るものは、
**あなたが見ていない五十二回の実行**です。**ディレクトリは狭く保ってください。**
