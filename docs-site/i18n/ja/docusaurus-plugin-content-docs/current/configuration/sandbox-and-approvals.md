# サンドボックスと承認

**二つの設定は、別々の仕事をしています。** サンドボックスは**エージェントに何が*できる*か**を、
承認は**何を先に訊かねばならないか**を決めます。

## サンドボックス

```toml
sandbox_mode = "workspace-write"
```

| | エージェントができること |
| --- | --- |
| `read-only` | ファイルを見る。変更はしない |
| `workspace-write` | 作業ディレクトリの中に書く |
| `danger-full-access` | あなたのアカウントにできること全部 |

**読み取りは決して制限されません。** 制限されるのは書き込みとネットワークだけなので、
`read-only` は「**ディスク全体が見えて、一つも変えられない**」という意味です。

### 書き込める根は作業ディレクトリです

`workspace-write` のもとでの「ワークスペース」とは、
**その対話または実行が開いているディレクトリ**のことです。
プロジェクトでも、リポジトリでもなく、**そのディレクトリ**です。

**このページで最も重要な一文がこれです。** ホームディレクトリで開いた実行は、
`.ssh`、`Documents`、`Library` に書けます。

**これは仮定の話ではありません。** 部門が存在する前に作られた定時タスクが
**ホームディレクトリを抱えたまま、そのやり方で四十二回走っていました**。
毎回そのすべてに手が届く状態で、**誰も訊かれず、何も言われませんでした**。
新しい対話の既定を変えても、それには触れませんでした —— **既定は遡らない**からです。

だから、**実行が始まる瞬間に二つ目の検査**があります。

## バックグラウンド実行がどこで始められるか

実行が始められるのは、そのディレクトリが**この製品がすでに知っている場所**のときです:

- ワークスペースの中
- ある部門のディレクトリの中
- **あなたが名指しで許可した場所**

それ以外は**保留**され、Dispatch パネルの**あなた待ち**の下に
*このディレクトリを許可* ボタンつきで現れます。
**ある場所を許可すると、それを待っていた実行がすべて解放されます。**

**訊くことが要点です**:普段と違う場所で走らせるのは、たいてい**まさに望まれたこと**であり、
答えは**拒否ではなく一つの問い**です。

## 承認

```toml
approval_policy = "on-failure"
```

| | |
| --- | --- |
| `untrusted` | 安全と分かっていないコマンドは毎回先に見せる |
| `on-failure` | コマンドは無人で走り、もっと権限が要るときだけ訊かれる |
| `never` | 実行前に何も見せない |

`never` は**何も保留されない**ことも意味します。承認を切った人は、**言葉どおり
「止められたくない」と言った**のであり、**それをもっと狭い意味だと決めつけるのは、
製品が自分の設定を上書きすること**になります。

**スクリプトを放しても構わないディレクトリ**に使ってください。

## 人がはまる組み合わせ

`sandbox_mode = "danger-full-access"` と `approval_policy = "never"` の組み合わせは、
**何も見せず何も訊かずに、あなたのマシンで任意のコマンドを走らせるエージェント**です。
**それが正解のディレクトリはあります。あなたのホームディレクトリはその一つではありません。**

## サンドボックスがしない二つのこと

- **モデルがあなたのファイルを読むのを止めません。** 読み取りは**どのモードでも**制限されません。
- **走らせたコマンドがそのあと何をするかは覆いません。** エージェントが起動したスクリプトは
  サンドボックスを継ぎますが、**実行より長生きするサービスを起動した場合、それは継ぎません**。
