# 첫 대화

## 어디서 시작하는가

새 대화는 `~/.opencli/workspace` 에서 열립니다 —— 어떤 부서에 속한 대화라면
그 부서의 디렉터리에서 열립니다.

**이건 보이는 것보다 중요합니다.** 에이전트의 샌드박스는 작업 디렉터리 안이라면 어디에나
쓸 수 있으므로, **대화가 열려 있는 디렉터리가 곧 바뀔 수 있는 범위의 전부**입니다.
예전에는 홈 디렉터리가 기본이었지만 이제는 아니고, 그 이유는
[샌드박스와 승인](/configuration/sandbox-and-approvals)에 있습니다.

입력창 위의 폴더 버튼으로 바꿉니다.

## 무언가를 부탁하기

평범한 문장이면 됩니다. 에이전트에게는 당신의 파일, 셸, 그리고 당신이 추가한
[커넥터](/doing-work/connectors)가 있습니다:

```
invoices.csv 를 읽고 rules.md 의 규칙을 어기는 행을 전부 나열해 줘
```

```
이 저장소에서 지난 한 주 동안 무엇이 바뀌었지?
```

```
their-draft.md 와 our-terms.md 를 비교해서 다른 조항을 전부 나열해 줘
```

## 무엇이 바뀌기 전에 일어나는 일

기본값에서는 **안전하다고 알려지지 않은 명령은 실행 전에 보여 주고**,
**파일 쓰기는 하기 전에 보여 줍니다.** 하나씩 승인하거나 거부하세요.

**Customize** 에 있는 세 가지 설정:

| | |
| --- | --- |
| **낯선 것은 무엇이든 먼저 묻기** | 안전하다고 알려지지 않은 명령을 매번 먼저 보여 줍니다 |
| **실패한 뒤에만 묻기** | 명령은 지켜보지 않아도 돌아가고, 더 많은 권한이 필요할 때만 묻습니다 |
| **절대 묻지 않기** | 실행 전에 아무것도 보여 주지 않습니다 |

마지막 것은 **스크립트를 마음대로 풀어놔도 괜찮은 디렉터리**를 위한 것입니다. 자세한 설명은
[샌드박스와 승인](/configuration/sandbox-and-approvals)에 있습니다.

## 무엇을 했는지 보기

**Artifacts** 는 이 대화에서 에이전트가 편집한 파일을 차이와 함께 보여 줍니다.
솔직한 한계 하나: **여기에는 에이전트의 파일 편집 도구로 한 편집만 올라옵니다.**
에이전트가 실행한 셸 명령이 쓴 파일 —— heredoc, 스크립트, `git checkout` —— 은
추적되지 않고 여기 나타나지 않습니다.

## 이야기가 다 안 들어가게 되면

길어진 대화는 **계속 들어맞도록 요약됩니다.**
**Summarising the conversation…** 가 보이고, 그다음부터 스레드는 예전 주고받음 대신
요약을 놓고 이어집니다.

**요약해도 소용이 없을 때** —— 길이가 대화가 아니라 도구 스키마에서 오는 경우 ——
**매 차례 다시 하는 대신 한 번만 그렇다고 말합니다.**

[부서를 하나 만드세요](/doing-work/departments-and-bots).
