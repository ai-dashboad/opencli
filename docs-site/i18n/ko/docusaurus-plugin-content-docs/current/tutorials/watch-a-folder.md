# 폴더를 지켜보고 무엇이 바뀌었는지 보고받기

**십 분.** 끝나면 **당신이 고른 주기로, 어떤 디렉터리에서 무엇이 움직였는지 짧게 적어
주는 무언가**가 생깁니다 —— 프로젝트, 공유 드라이브, **누군가 자꾸 뭔가를 놓고 가는 폴더**.

## 1. 대화를 그 폴더로 향하게 하기

새 대화를 열고 입력창 위의 폴더 버튼으로 디렉터리를 고릅니다.

**이건 보이는 것보다 중요합니다**: **에이전트는 대화가 열려 있는 디렉터리 안이라면
어디에나 쓸 수 있고**, 그 밖에는 못 씁니다. **폴더를 고르는 것은 폭발 반경을 고르는
일입니다.**

## 2. 보고를 한 번 시켜 보기

```
이 폴더에 weekly-report 스킬을 써 줘.
```

`weekly-report` 스킬은 제품에 들어 있습니다. **무엇이 바뀌었는지 알아내고** ——
폴더가 저장소라면 git 에서, 아니면 수정 시각에서 —— 세 절을 씁니다:
**끝난 것, 진행 중인 것, 그리고 결정이 필요한 것.**

**마지막 절이 이걸 읽는 이유입니다.**

## 3. 주기에 올리기

**백그라운드 실행 → 되풀이되는 것 하나 만들기:**

| 칸 | |
| --- | --- |
| **무엇을 하게 할지** | 이 폴더에 weekly-report 스킬을 쓴다. `report-<date>.md` 로 저장한다. |
| **이름** | 주간 보고 |
| **얼마나 자주** | 7일 |
| **어디서 돌릴지** | 당신이 고른 폴더 |

## 4. 어디서 돌지 확인하기

**폴더가 작업공간 안도 아니고 부서도 아니라면, 첫 실행은 시작되는 대신 붙들리고**
*당신을 기다림* 아래에 나타납니다.

**의도된 것입니다.** 디렉터리를 허용하거나, 작업을 부서 안으로 옮기세요.

## 5. 첫 보고를 읽기

**Run now**, 그다음 실행을 열어 **만들어지는 대로 출력을 읽습니다.**

**보고가 얄팍하면 그 폴더의 한 주가 얄팍했던 것입니다** —— 이 스킬은
**분량을 채우는 대신 한 줄로 그렇게 말하라고** 지시받았습니다.
**텅 빈 한 주에서 부풀린 보고는 사람들에게 보고를 건너뛰라고 가르치기 때문입니다.**

## 남의 폴더에 이걸 할 때

**조심할 값어치가 있는 것이 둘.**

**에이전트는 향한 것을 전부 읽습니다.** 그리고 **읽기는 어느 모드에서도 샌드박스에
제한되지 않습니다.** **모델 공급자에게 보내고 싶지 않은 것이 든 폴더를 향하게 해서는
안 됩니다** —— **모델이 당신 기계에 있는 경우가 아니라면.** 그때는 아무것도 밖으로
나가지 않습니다.

**주기는 당신의 주의보다 오래 삽니다.** 일 년 동안 주 1회 도는 것은
**당신이 지켜보지 않은 쉰두 번의 실행**입니다. **디렉터리를 좁게 유지하세요.**
