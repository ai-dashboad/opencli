# 문제 해결

## 자격 증명이 거부되었다고 나옵니다

```
The model provider would not accept the request without credentials.
(status 401 Unauthorized)
```

**고른 공급자에 키가 설정되지 않았거나, 설정된 키가 거기서는 유효하지 않은 것**입니다.
**순서대로 셋**을 확인하세요:

1. **실제로 어떤 공급자가 골라져 있는지** —— `config.toml` 의 `model`, 또는 입력창의
   선택기. **한 번도 설정하지 않은 공급자의 모델을 가리키고 있는 것**이 흔한 원인입니다.
2. **`env_key` 가 지목하는 환경 변수**가 **에이전트가 도는 셸**에 설정되어 있을 것.
   **데스크톱 앱은 그것을 당신의 셸이 아니라 키를 보관하는 자리에서 읽습니다.**
3. **그 키가 그 공급자의 것일 것.** 한 곳의 키는 다른 곳의 키가 아닙니다.

**401은 일부러 재시도하지 않습니다**: **자격 증명은 다시 내민다고 유효해지지 않습니다.**

## 모델 목록이 비어 있습니다

**Models** 패널도 입력창의 선택기도 공급자의 `/v1/models` 에서 옵니다.
**빈 목록은 그 요청이 실패했다는 뜻**이고, 이유는 `~/.opencli/log` 에 있습니다.

**키를 요구하는 공급자는 키 없이는 아무것도 돌려주지 않으므로**, 이것과 위의 401은
**보통 같은 문제**입니다.

## 대답은 하는데 제 파일은 절대 건드리지 않습니다

**당신의 모델이 도구를 부르지 않는 것입니다.** 이것이 **가장 흔한 실망**이고,
**설정 실수가 아닙니다** —— **그냥 부르지 않는 모델이 있습니다.**

[시험해 보세요](/reference/checking-a-model). 5분, 정해진 과제 하나.
**떨어지면 그 모델은 이 일에 맞는 도구가 아니고, 어떤 설정으로도 그건 바뀌지 않습니다.**

## 파일을 제대로 읽지 않고 `grep` 을 돌립니다

**같은 밑바탕의 빈틈이 좀 더 순한 형태로 나온 것**입니다: 에이전트 쪽으로 훈련되지 않은
모델은 **눈앞에 파일 도구가 있어도 셸에 손을 뻗습니다.**
**화면의 그 무엇도 그 틈을 메우지 못합니다.**

## 백그라운드 실행이 저를 기다린다고 합니다

**그 작업 디렉터리가 이 제품이 아는 곳이 아닙니다** —— 작업공간도, 부서의 디렉터리도,
**당신이 이름으로 허락한 곳**도 아닙니다.

Dispatch 패널에서 **이 디렉터리 허용** 을 하거나, 작업을 부서로 **옮기세요**.
**돌리는 대신 붙들어 두는 이유는, 실행이 그 디렉터리 안이라면 어디에나 쓸 수 있기
때문입니다.**

## 예약 작업이 한 번도 돌지 않았습니다

**가능성은 둘**:

- **OpenCLI가 닫혀 있었다.** 예약된 일은 **열려 있는 동안에만** 돕니다.
- **붙들려 있다**, 위와 같이. 붙들린 작업은 *당신을 기다림* 아래에 나타납니다.

## 대화가 자꾸 스스로를 요약합니다

**요약하자마자 또 필요하다면, 길이는 대화에서 오는 게 아닙니다** ——
**매 요청의 고정된 부분**, 그러니까 **대개는 당신 커넥터들의 도구 스키마**입니다.
**커넥터 넷이면 당신이 아직 아무 말도 하기 전에 만 토큰이 될 수 있습니다.**

**매 차례 되풀이하는 대신 한 번 그렇게 말합니다.** 그 대화에서 쓰지 않는 커넥터를 끄는
것이 해법입니다.

## 데스크톱 앱이 열리지 않습니다

**macOS**: `xattr -dr com.apple.quarantine /Applications/OpenCLI.app` 를 실행하거나
오른쪽 클릭 → **열기**.

**Windows**: SmartScreen → **추가 정보** → **실행**.

그래도 거부하면 **내려받기가 온전하지 않을 수 있습니다** —— 릴리스 페이지의 파일 크기와
맞춰 보세요.

## 에이전트가 제가 못 본 무언가를 했습니다

**Artifacts 에는 에이전트의 파일 편집 도구로 한 편집만 올라옵니다.** 에이전트가 돌린 셸
명령이 쓴 파일 —— heredoc, 스크립트, `git checkout` —— 은 **진짜 변경이지만 거기에
나타나지 않습니다.**

**작업 디렉터리에서의 `git status` 가 믿을 만한 답입니다.**

## 다른 언어를 골랐는데 화면이 영어입니다

**사전은 그 언어가 골라질 때 받아 오므로** **영어가 보이는 순간**이 있습니다.
계속 영어라면 **그 조각이 로드되지 않은 것**입니다 —— 데스크톱 앱의 개발자 도구에서
브라우저 콘솔을 보세요.

**번역이 없는 문장은 설계상 언제나 영어로 나옵니다.** 그건 **절반쯤 된 번역이지 고장이
아닙니다.**

## 로그가 있는 곳

```
~/.opencli/log
```

**Settings → About → Logs** 가 그 디렉터리를 엽니다. 문제를 보고할 때는
**실패 앞뒤 오십 줄이면 거의 충분합니다** —— 그리고 **붙여 넣기 전에 키가 들어 있는지
확인하세요.**
